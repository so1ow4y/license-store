# License Store

Платформа для продажи цифровых товаров по лицензиям: магазин с каталогом и
тарифами, приём оплаты несколькими способами, автоматическая выдача ключей,
личный кабинет покупателя, оптовые продажи через реселлеров и админка с
ролями и журналом событий.

Подходит для всего, что продаётся как «ключ на срок»: программы, подписки,
доступ к сервисам. Для десктопных программ есть дополнительный модуль —
защищённая выдача сборок через загрузчик (см. [ниже](#защищённая-выдача-программ-необязательно)).

**Стек:** NestJS 11 (Fastify, SWC) · Prisma 6 · PostgreSQL 17 · Redis 7 ·
S3 (RustFS) · React 19 + Vite + TanStack Router/Query + Tailwind 4 + shadcn/ui ·
Docker. Модульный монолит: один процесс API, горизонтально масштабируется
репликами за nginx.

## Что умеет

### Магазин и покупатель

- каталог товаров с тарифами: срок, цена, валюта, бессрочные тарифы;
- регистрация по почте, через Discord или Telegram, по ключу активации; 2FA;
- «Мои лицензии», «Мои заказы», активация ключа или покупки Digiseller;
- уведомления на почту и в Telegram-бот; интерфейс на русском и английском.

### Оплата

Каждый способ включается и настраивается в админке:

| Способ | Как работает |
|---|---|
| ЮKassa | редирект на оплату, статус приходит вебхуком и перепроверяется через API; лицензия выдаётся автоматически |
| Криптовалюта | покупатель видит сумму в монетах, адрес и QR, присылает хеш транзакции; оплату подтверждает сотрудник |
| Digiseller | покупка на площадке, активация по коду или номеру заказа |
| Вручную | сотрудник выдаёт лицензию или ключ активации сам |

Реквизиты заводятся шаблонами (общие для магазина) или лично для товара; у
товара может быть несколько кошельков. Ключи ЮKassa и Digiseller хранятся в
базе зашифрованными и наружу не отдаются.

### Лицензии

- выдача по оплате, вручную или по ключу активации; продление, блокировка,
  отзыв, массовые действия;
- у каждой лицензии видно, откуда она (заказ, реселлер, выдал сотрудник) и
  кто и когда её активировал;
- поиск по строке запроса: `product:… status:… user:… reseller:…`.

### Реселлеры (оптовые продажи)

- реселлер пополняет баланс: заявкой с переводом криптой (подтверждает
  сотрудник) или через администратора;
- выпускает ключи активации со своего баланса по цене со скидкой и продаёт их
  своим клиентам по своей цене; неиспользованный ключ можно отменить с
  возвратом денег;
- видит своих клиентов, продлевает им лицензии, сбрасывает привязку в пределах
  суточного лимита;
- условия задаёт администратор: скидка, кредитный лимит, разрешённые товары;
  вся история операций по балансу сохраняется.

### Админка

- товары, тарифы, сборки (файлы в S3, загрузка прямо из браузера);
- заказы и подтверждение оплаты, зависшие сделки Digiseller;
- способы оплаты и реквизиты;
- пользователи: роли, блокировка, массовые действия;
- реселлеры и заявки на пополнение баланса;
- безопасность: поиск по журналу событий и входов, блокировки по IP;
- настройки, которые меняются без деплоя.

### Роли

| Роль | Что может |
|---|---|
| `super_admin` | всё |
| `security_admin` | журналы событий и входов, адреса пользователей, блокировка аккаунтов и IP |
| `product_admin` | товары, тарифы, сборки, реквизиты оплаты |
| `support` | заказы и подтверждение оплат (в том числе пополнений реселлеров), лицензии, сбросы привязки, блокировка аккаунтов |
| `reseller` | панель «Мои продажи» |
| `user` | свои лицензии, заказы и устройства |

Начиная с `support` вход без 2FA невозможен: при первом входе система сама
попросит её включить. Назначать можно только роли ниже своей.

### Защищённая выдача программ (необязательно)

Для десктопных программ с загрузчиком на C++: загрузчик проверяет лицензию
подписанными запросами, лицензия привязывается к устройству (сбросы
ограничены), сборка выдаётся зашифрованной под конкретную сессию. Контракт —
[docs/TZ-LAUNCHER.md](docs/TZ-LAUNCHER.md). Если продаются не программы,
модуль просто не используется.

## Быстрый старт (Linux / WSL2 Ubuntu)

Нужны Docker Engine с compose-плагином и Node.js 22+.

```bash
cp .env.example .env
openssl rand -hex 32   # три раза: JWT_SECRET, HWID_PEPPER, ENCRYPTION_KEY
```

Подставь три разных значения в `.env`, затем:

```bash
docker compose up -d                     # postgres, redis, s3, mailpit, nginx
cd apps/api && npm install
npx prisma migrate deploy && npm run db:seed
npm run dev                              # API на :3000, горячая перезагрузка
```

Во втором терминале:

```bash
cd apps/web && npm install && npm run dev   # сайт на :5173
```

Вход: логин `admin`, пароль `ChangeMe!2026` (или значение
`SEED_ADMIN_PASSWORD` из `.env`). При первом входе понадобится приложение-
аутентификатор для 2FA. Каталог после сида пустой — товары заводятся в
админке.

Сид идемпотентен: повторный запуск обновляет роли, права, настройки и
шаблоны писем, но не трогает товары, пользователей и уже настроенные способы
оплаты.

## Адреса

| Адрес | Что это |
|---|---|
| http://localhost:5173 | сайт (Vite) |
| http://localhost:3000/api/v1 | API напрямую |
| http://localhost:3000/docs | OpenAPI (только в разработке) |
| http://localhost:8080 | API через nginx, как на проде |
| http://localhost:8080/health/ready | readiness: Postgres и Redis доступны |
| http://localhost:8025 | Mailpit — все письма в разработке |
| http://localhost:9001 | консоль RustFS (`S3_ACCESS_KEY` / `S3_SECRET_KEY`) |

Postgres на хосте — `localhost:5442`, Redis — `localhost:6389`: порты
сдвинуты, чтобы не конфликтовать с другими локальными стеками. Бакеты S3 и
их CORS API создаёт сам при старте.

**Полный Docker** (проверка того, что поедет на сервер): поставь в `.env`
`API_UPSTREAM=api:3000` и выполни `docker compose --profile full up -d --build`.

## Команды

API (`apps/api`):

```bash
npm run dev          # запуск с горячей перезагрузкой
npm run build        # сборка через SWC
npm test             # vitest
npm run typecheck
npm run lint
npm run db:deploy    # применить миграции
npm run db:seed      # роли, права, настройки, шаблоны писем
npm run db:studio    # веб-интерфейс к данным
npm run db:partitions  # обслуживание партиций журналов
```

Сайт (`apps/web`): `npm run dev`, `npm run build`, `npm run typecheck`.
Маршруты TanStack Router генерируются в `src/routeTree.gen.ts` (файл в git).

В `scripts/` лежат деплой, бэкап, проверки почты и сквозные проверки против
запущенного API (`smoke-*.ps1|mjs`). Smoke-скрипты писались по этапам и
местами отстают от кода; многие рассчитаны на товар со slug `fc26`.

## Продакшен

`scripts/server-setup.sh` один раз готовит чистый сервер (docker, фаервол,
своп). `scripts/deploy.sh <IP> <домен> [почта]` копирует проект, собирает
образ, применяет миграции и сид, выпускает сертификат Let's Encrypt.
Секреты для сервера — `.env.production` (шаблон генерирует
`scripts/gen-secrets.ps1`). Бэкап базы, бакета и ключа шифрования —
`scripts/backup.sh`, проверка бэкапа восстановлением — `scripts/restore-check.sh`.

## Правила, которые легко нарушить

**Миграции.** Расширения Postgres объявляются только в `schema.prisma`.
`audit_logs` и `login_history` партиционированы, Prisma этого не умеет: при
изменении их структуры правь сгенерированный `migration.sql` по образцу
[`prisma/sql/01_partitioning.sql`](apps/api/prisma/sql/01_partitioning.sql).

**Алиасы путей** (`@common/...`) заводятся в трёх местах: `tsconfig.json`,
`.swcrc` и `vitest.config.ts`.

**Деньги** — только `Prisma.Decimal`; списание с баланса реселлера —
одним условным `UPDATE` в транзакции вместе с записью в историю операций.

**Контракт загрузчика неизменен байт в байт.** Подпись запросов и формат
payload описаны в [docs/TZ-LAUNCHER.md](docs/TZ-LAUNCHER.md) и проверяются
векторами из [docs/SIGNATURE-VECTORS.md](docs/SIGNATURE-VECTORS.md).

**Slug товара — до 32 символов**: ключ лицензии = SLUG + 20 символов,
колонка `VarChar(64)`.

## Секреты

`.env` в git не попадает. Значения генерируются через `openssl rand -hex 32`
и различаются между собой и между окружениями:

- `JWT_SECRET` — подпись access-токенов (смена разлогинивает всех);
- `ENCRYPTION_KEY` — шифрование полей БД: 2FA, привязки устройств, ключи
  способов оплаты; потеря = эти данные не восстановить;
- `HWID_PEPPER` — соль хеша привязки к устройству. **Не менять после
  запуска**: все привязки перестанут совпадать.
