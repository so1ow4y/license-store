# Центр безопасности и раздача загрузчика

Что появилось в ветке «Безопасность» админки, как это устроено и что нужно
включить на сервере, чтобы блокировки работали ниже приложения.

## Уровни блокировки адреса

| Уровень | Где отсекается | Кто применяет | Порты |
|---|---|---|---|
| Приложение (L7) | первым guard'ом API, до проверки токена | сам API, всегда | нет |
| nginx (L7, край) | `if ($lp_edge_blocked)` → 403 JSON, в API запрос не попадает | агент в контейнере nginx | нет |
| Фаервол (L3/L4) | nftables, `prerouting` с приоритетом `raw` (-300): до conntrack и DNAT докера, то есть до TCP-рукопожатия | контейнер `firewall` | можно ограничить |

Блок верхнего уровня действует и на нижних: если агент фаервола не запущен,
адрес всё равно получит 403 от nginx или API. Исключение — блок фаервола
только по не-веб портам (например, `22`): сайт с этого адреса продолжает
работать, закрыт только SSH. Веб-портами считаются 80, 443, 8080, 8443
(`WEB_PORTS` в `ip-block.service.ts`).

Нельзя заблокировать петлю (127.0.0.0/8, ::1), свой адрес, подсеть шире /16
(IPv4) и /32 (IPv6), а также адрес, с которого входит пользователь с ролью
не ниже твоей.

### Включение агентов

1. Сгенерировать токен и положить его в `.env` (его читают и API, и compose):

   ```bash
   echo "EDGE_AGENT_TOKEN=$(openssl rand -hex 32)" >> .env
   ```

2. Перезапустить API и пересоздать nginx:

   ```bash
   docker compose up -d --force-recreate nginx
   ```

   В логе nginx появится `30-lp-edge-sync.sh: синхронизация списков с API каждые 10 с`.
   Агент забирает `/api/v1/internal/edge/nginx/{blocklist,priority}`, при
   изменении проверяет конфиг (`nginx -t`) и делает `nginx -s reload`; битый
   файл откатывается к прежнему.

3. Фаервол (только Linux-хост или WSL2 с nftables, меняет сетевые правила машины):

   ```bash
   docker compose --profile firewall up -d firewall
   ```

   Агент держит свои правила в отдельной таблице `inet lp_guard` и удаляет её
   при остановке. Проверить сценарий без хоста: собрать образ `docker/firewall`
   и выполнить в нём `nft -c -f` с `--network none --cap-add NET_ADMIN`.

Состояние агентов видно на странице «Блокировки» (карточка «Уровни блокировки»).

## Приоритет трафика (DDoS)

Каждому запросу к API до разбора тела назначается вес 0–100 — максимум из
веса доверенного адреса, пользователя (явный вес или вес роли), «пропуска
приоритета» и базового веса анонима / вошедшего. Дальше — очередь:

- в работе одновременно не больше `maxConcurrent` запросов (вдвое меньше,
  если p99 задержки цикла событий выше `lagThresholdMs`);
- лишние ждут, освободившийся слот получает самый тяжёлый;
- вес не ниже `bypassWeight` проходит мимо очереди;
- при переполнении очереди выбывает самый лёгкий, ожидание дольше
  `queueTimeoutMs` — 503 с `Retry-After`;
- «режим атаки»: всё легче `attackMinWeight` сразу получает 503. Включить
  его нельзя, если включающий сам под него попадает.

«Пропуск приоритета» — подписанная метка (заголовок `X-Priority-Pass`),
которую браузер доверенного пользователя получает после входа и хранит
30 дней. С ней администратор входит заново даже во время атаки, пока
токена ещё нет. Доступа метка не даёт — только место в очереди.

Доверенные адреса дополнительно выходят из-под `limit_req`/`limit_conn`
nginx и никогда не блокируются правилами корреляции.

Пути `/health`, `/api/v1/internal/edge/*` и `/api/v1/launcher/payload`
очередь не проходят (у выдачи payload своя очередь по байтам).

Очередь — в пределах процесса: у каждой реплики своя.

## Правила корреляции

Раз в 30 секунд (одна реплика, замок в Redis) каждое включённое правило
считает события своего журнала за окно по строке поиска (тот же язык, что
в обозревателе), группирует по полю и сравнивает с порогом — либо число
событий, либо число разных значений другого поля. Новая группа за порогом —
сработка и действие: только сработка, блок адреса на выбранном уровне и
портах или блок пользователя. Повтор по тому же ключу — не раньше паузы.

Правила не блокируют доверенные адреса, адреса сотрудников и самих
сотрудников. Сид создаёт пять примеров выключенными.

## Дашборды

Свои у каждого, можно сделать общими. Виджеты: счётчик, гистограмма, топ
значений, последние события, сработки, нагрузка, блокировки. Период общий,
выделение на гистограмме приближает весь дашборд.

## Загрузчик

Право `launcher.manage` (по умолчанию у администратора товаров). Релиз:
версия, платформа, канал, «что нового», аудитория (`PUBLIC` — кнопка и на
главной, `USERS`, `LICENSED` — владельцы действующей лицензии, `ROLES`).
Файл идёт в бакет релизов по presigned PUT, SHA-256 считает сервер.
Скачивание — всегда через API: проверка доступа, счётчик, ссылка на 5 минут.
Требования и шаги установки — настройка `launcher.page`.

Главная страница платформы — `/`, кабинет — `/licenses`. Название платформы
задаётся `VITE_BRAND_NAME` при сборке фронтенда.
